Проект: VANTA  
Тип проекта: интернет-магазин одежды и аксессуаров  
Тематика: современная streetwear / casual одежда

1. ОБЩАЯ ИНФОРМАЦИЯ

Необходимо разработать полноценный frontend интернет-магазина VANTA.

VANTA — современный бренд одежды, продающий футболки, худи, свитшоты, брюки, куртки, обувь и аксессуары.

Основная задача сайта — предоставить пользователю удобный интерфейс для просмотра каталога, поиска и фильтрации товаров, просмотра подробной информации о товаре, добавления товаров в избранное и корзину, а также оформления заказа.

Проект должен выглядеть как реальный коммерческий интернет-магазин, а не как учебный каталог карточек.

Дизайн минималистичный и современный.

Основная цветовая палитра:

белый;  
чёрный;  
серый;  
светло-серый.

Допускается использование одного акцентного цвета.

Основной акцент необходимо сделать на фотографиях товаров, типографике и удобстве интерфейса.

51. АРХИТЕКТУРА JAVASCRIPT

Не писать весь проект в одном файле script.js на несколько тысяч строк.

Разделить функциональность на модули.

Например:

products.js

catalog.js

filters.js

search.js

cart.js

wishlist.js

storage.js

product.js

checkout.js

validation.js

modal.js

toast.js

utils.js

Названия являются примером. Конкретную архитектуру разработчик выбирает самостоятельно.

52. РАБОТА С API — ДОПОЛНИТЕЛЬНЫЙ УРОВЕНЬ

После завершения локальной версии переделать получение товаров на асинхронное.

Создать локальный JSON или использовать mock API.

Например:

GET /products

GET /products/:id

Сделать:

loading;

success;

error states.

Использовать fetch и async/await.

Обязательно обработать ошибку загрузки.

Например:

Something went wrong.

Кнопка:

TRY AGAIN

53. ТЁМНАЯ ТЕМА — ДОПОЛНИТЕЛЬНО

Добавить Light / Dark mode.

Сохранять выбор пользователя в localStorage.

При первом посещении учитывать prefers-color-scheme.

Не допускать появления светлой темы на долю секунды перед загрузкой сохранённой тёмной темы.

54. СЛОЖНЫЙ УРОВЕНЬ — INVENTORY

У каждого товара и его варианта должен быть остаток.

Например:

Black / M — 5

Black / L — 0

Grey / M — 2

Если конкретная комбинация цвета и размера закончилась, пользователь не должен иметь возможность добавить её в корзину.

Показывать:

Out of stock

или:

Only 2 left

Это должно зависеть именно от выбранного варианта товара, а не только от общего stock товара.

55. СЛОЖНЫЙ УРОВЕНЬ — ЦЕНА

Создать единую систему расчёта цены.

Итог заказа должен рассчитываться из:

стоимости товаров;

количества;

скидок на товары;

промокода;

стоимости доставки.

Нельзя отдельно рассчитывать Total в Header, Cart Drawer, Cart и Checkout разными формулами.

Все компоненты должны использовать одну и ту же бизнес-логику.

56. СЛОЖНЫЙ УРОВЕНЬ — СОСТОЯНИЕ

После обновления страницы должны сохраняться:

корзина;

избранное;

недавно просмотренные товары;

тема;

применимый промокод.

Фильтры и сортировка каталога должны восстанавливаться из URL.

Нельзя сохранять в localStorage полностью скопированные объекты товаров, если достаточно сохранить ID, вариант и количество.

57. EDGE CASES

Проект должен корректно обрабатывать нестандартные действия пользователя.

Проверить следующие ситуации:

Пользователь дважды добавляет одинаковый товар одного размера.

Пользователь добавляет один товар разных размеров.

Пользователь пытается купить больше единиц, чем есть на складе.

Товар в корзине закончился.

Пользователь удаляет последний товар из корзины.

Пользователь применяет неправильный промокод.

Пользователь применяет промокод повторно.

Пользователь меняет способ доставки.

Пользователь обновляет страницу во время checkout.

Пользователь открывает несуществующий ID товара.

Пользователь вручную вводит некорректные query parameters в URL.

Каталог после фильтрации содержит 0 товаров.

Поиск содержит только пробелы.

Пользователь быстро несколько раз нажимает ADD TO CART.

Интерфейс не должен ломаться ни в одном из этих случаев.

58. UX-ТРЕБОВАНИЯ

После действия пользователя интерфейс должен давать понятную обратную связь.

Если товар добавлен в корзину — пользователь должен это увидеть.

Если возникла ошибка — пользователь должен понимать причину.

Если выполняется загрузка — необходимо показать loading state.

Если действие невозможно — соответствующий элемент должен быть disabled.

Нельзя заставлять пользователя угадывать, произошло действие или нет.

59. КРИТЕРИИ ПРИЁМКИ

Проект считается завершённым, если:

реализована главная страница;

работает каталог;

есть минимум 24 товара;

товары генерируются из данных;

работает поиск;

работает debounce поиска;

работают фильтры;

работает галерея;

нельзя добавить недоступный вариант товара;

работает Quick View;

Wishlist сохраняется после перезагрузки;

работает корзина;

корзина сохраняется после перезагрузки;

количество товаров изменяется;

стоимость пересчитывается автоматически;

работают промокоды;

стоимость доставки рассчитывается корректно;

нельзя перейти к следующему этапу Checkout с некорректными данными;

есть 404;

сайт адаптивен;

нет случайного горизонтального скролла;

состояние приложения корректно восстанавливается после перезагрузки.

60. ОГРАНИЧЕНИЯ

Для учебного проекта не требуется:

настоящая банковская оплата;

регистрация настоящих пользователей;

настоящая отправка заказов;

настоящая база данных;

административная панель;

реальная интеграция со службой доставки.

Все эти процессы допускается имитировать на frontend.

При этом интерфейс должен вести себя так, будто приложение работает с реальным backend.

Необходимо разработать не просто красивую страницу с карточками товаров, а полноценное frontend-приложение интернет-магазина.

управления состоянием интерфейса;

accessibility;

SEO;

оптимизации производительности;

проектирования пользовательского интерфейса.
